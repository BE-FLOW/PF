## 2026-09-01 프로필 사진과 예방접종 입력 개선

- 프로필 사진 저장 성공은 비공개 파일 업로드와 DB 연결뿐 아니라 새 서명 URL 표시까지
  확인한 뒤 안내한다. 서명 URL이 만료되거나 클라이언트 발급이 실패하면 서버가 다시
  소유권을 확인해 짧은 URL을 갱신한다.
- 강아지 접종명은 `종합백신`, `광견병`, `코로나 장염`, `켄넬코프`,
  `개 인플루엔자`, `기타`를 가로 선택 목록으로 제공한다. 이는 실제 기록을 쉽게 찾기
  위한 목록이며 필수·권장 접종표가 아니다.
- 백신 이름만 보고 다음 날짜를 일률적으로 추정하지 않는다. 보호자가 병원이나
  접종카드에서 확인한 주기를 한 번 선택하면 이후 맞은 날 변경에 맞춰 자동 계산하고,
  직접 안내받은 날짜로 언제든 수정할 수 있다.
- 저장 완료 화면에서는 입력 폼의 `일정 있음` 배지를 반복하지 않고 가장 가까운 일정의
  날짜, D-day, 오늘 또는 지난 상태를 작은 보조 카드로 보여 준다. 홈의 병원 전달본 준비
  행동보다 강조하지 않는다.
- DB의 여러 예방접종 행을 접종 종류별로 다시 불러와 수정하며, 다른 종류를 선택할 때
  기존 행의 ID를 재사용해 덮어쓰지 않는다.

## 2026-09-03 누적 예방관리와 검사 사실 기록

- 다른 예방접종 칩을 누르면 기존 행을 불러와 덮어쓰지 않고 새 접종 기록을 시작한다.
  저장된 행을 명시적으로 눌렀을 때만 해당 행을 수정하며 각 행은 따로 삭제할 수 있다.
- 심장사상충과 내·외부 기생충 관리는 접종과 분리한다. 실제 완료 뒤 한 번 눌러 오늘
  날짜를 보호자 기록으로 남기며, 병원이나 제품 안내를 대신하는 권장 일정으로
  표현하지 않는다. 지난 기록도 조회·삭제할 수 있다.
- 검사 기록은 검사일, 검사명, 보호자가 옮긴 결과, 선택 병원명·메모만 저장한다.
  선택 기간의 사실 자료와 함께 보이고 공유되지만 AI 질병·원인 추론에는 사용하지
  않는다.
- 생일·접종일·검사일은 숫자 8자리 입력을 자동 서식화하며 미래 날짜를 막는다.
  다음 접종 안내 날짜만 미래를 허용한다.
- 이 보조 기록은 홈의 `병원 준비` 주요 행동과 경쟁하지 않도록 작게 두고, 검사 입력
  관리는 전달본 날짜 선택 아래에 둔다.

## 2026-06-15 방향 전환

- 단건 입력의 결과는 `리포트`가 아니라 `오늘 기록`으로 부른다.
- 제품의 핵심 결과는 반려동물별 누적 `건강 흐름`이다.
- 최근 14일 기록에서 반복 증상, 식욕·활력 변화, 위험 점수 흐름을 계산한다.
- 누적 흐름은 진단이나 예측이 아니라 보호자 기록의 정리다.
- AI가 없어도 같은 기록은 같은 흐름 판단을 내리도록 결정론적으로 계산한다.
- 건강 흐름은 최종 리포트가 아니라 다음 사건과 병원 상담을 이해하는 맥락이다.

## 2026-06-15 SOAP-LOOP 방향 (과거 결정)

- 다음 제품 단위는 서로 떨어진 기록이 아니라 관찰, 병원 전달, 계획, 경과가
  이어지는 `episode`다.
- 보호자가 병원에서 받은 계획을 입력한 경우와 수의사가 직접 확인한 경우를
  같은 상태로 취급하지 않는다.
- 화면에는 SOAP 전문 용어 대신 `기록`, `병원 전달본`,
  `병원에서 받은 안내`, `건강 흐름`을 사용한다.
- 병원 대시보드, RAG, 지식그래프는 반복 병원 사용과 기록 재사용이 확인된 뒤 검토한다.
- 당시 검토한 병원 전달본 판매 가설은 2026-08-18 무료 공개 결정으로 폐기됐다.
- v0.3 병원 전달은 기기 공유와 복사로 시작한다. 만료·접근 통제가 필요한 공개
  링크는 별도 보안 설계 전까지 만들지 않는다.

## UX 원칙

1. 같은 정보는 두 번 묻지 않는다.
2. 필수 항목은 핵심 흐름에 꼭 필요한 것만 둔다.
3. 정상 상태는 한 번의 선택으로 기록할 수 있어야 한다.
4. 전문 용어보다 보호자가 실제로 관찰한 표현을 사용한다.
5. 메뉴는 데이터와 사용 이유가 생긴 뒤 추가한다.

## 2026-07-20 기본 화면 경량화

- 홈은 `오늘 기록`과 `현재 상태` 두 카드만 기본으로 보여준다. 체크스코어와
  14일 흐름처럼 같은 판단에 쓰이는 정보는 한 카드로 합친다.
- 정상 상태는 `평소와 같음` 한 번으로 바로 저장한다. 증상, 위험 신호, 메모,
  첨부는 변화가 있을 때만 펼친다.
- 건강 흐름은 사건별 상태와 `보기`만 먼저 보여준다. 병원 요약, 계획, 경과,
  수정·삭제는 사건을 펼친 뒤에 제공한다.
- 사용법 설명은 첫 설정과 필요한 상세 화면에 둔다. 반복 사용 화면에는 제목,
  현재 상태, 다음 행동만 남긴다.
- 웹과 앱의 정보 우선순위와 문구를 맞추되, 각 화면 크기에 맞는 배치는 허용한다.

## 2026-07-22 기록과 흐름 통합

- 날짜 선택, 짧은 글, 사진·영상 첨부를 하나의 기록 작성 흐름에 둔다.
- 기록은 같은 반려동물의 시간 흐름에 자동 연결하며 별도 경과 입력을 요구하지 않는다.
- 건강 흐름은 달력과 날짜 범위 선택을 중심으로 보고, 반복되는 접기·펼치기를 줄인다.
- 병원 전달본과 AI 정리는 사용자가 고른 기간의 사실 기록만 사용한다.
- 흐름 마무리 버튼과 정해진 3·7·14·30·60·90일 입력 일정을 사용자에게 요구하지 않는다.

## 2026-07-23 판매 가설 (2026-08-18 전체 폐기)

이 시기에는 앱 안의 단건 상품으로 병원 전달본 수요를 검증하는 방안을 검토했다.
2026-08-18 완전 무료 공개 결정으로 상품·가격·이용권·결제 흐름에 관한 당시 판단을
모두 폐기했다. 이 기록은 결정 이력일 뿐 현재 구현·스토어·심사 요구사항으로 사용하지
않는다. 앱 우선, 사용자 소유 기록의 자유로운 수정·삭제와 단순한 병원 전달 경험은
무료 공개 계약에 맞게 계속 유지한다.

## 2026-07-29 병원 직전 사용 우선

- 현재 주 사용자는 꾸준한 건강관리 습관을 만들 사람보다 병원 방문이 임박해
  설명 자료가 당장 필요한 보호자다.
- 홈의 첫 행동은 `병원 전달본 준비` 하나로 두고 체크스코어, 예방접종, 장기 흐름은
  첫 화면의 주요 행동과 경쟁시키지 않는다.
- 첫 등록은 이름과 종류만 요구한다. 사진, 품종, 생일, 성별, 체중과 예방접종은
  선택 영역에 두고 나중에 보완할 수 있게 한다.
- 한 줄 또는 사진으로 기록을 시작하고 저장 직후 기본 사실 요약과 전달본 생성을
  보여준다.
- 증상을 선택했을 때만 수의사가 자주 묻는 핵심 사실 태그를 한 줄로 보여준다.
  답변은 선택 사항이고 별도 설문 화면이나 필수 단계는 만들지 않는다.
- 전달본은 선택한 태그를 사실로 보존하고 이미 답한 내용을 추가 질문으로 반복하지
  않는다.
- `병원 준비 시작 → 기록 저장 → 전달본 생성 → 공유` 완료율과 3분 내 완료 여부를
  일일 활성 사용자나 연속 기록보다 먼저 검증한다.

## 2026-08-04 방향 고정

- 앱의 기본 동선은 `홈 → 병원 준비 → 전달본 → 계정`으로 고정한다. 웹은 같은
  용어를 쓰는 보조 화면이며 별도 제품 흐름을 만들지 않는다.
- 전달본의 중심은 보호자의 원문 한 줄, 실제 관찰 시점, 선택한 사실과 첨부다.
  체크스코어와 앱 안전 단계는 보호자 안내일 뿐 병원용 사실에 넣지 않는다.
- 고정 14일 요약, 3·7·14일 경과 입력, 수동 흐름 마무리와 병원 안내 완료 체크를
  사용자 행동으로 요구하지 않는다.
- 당시에는 병원에서 들은 내용을 다음 전달본에 자동으로 이어 붙이기로 했으나,
  2026-08-18 무료 공개 결정에서 방문 경계와 출처를 숨기는 자동 복사를 보류했다.

## 2026-08-18 완전 무료 공개

- 사업자 등록과 유료 판매 준비가 끝날 때까지 Android와 iOS 공개판을 완전 무료로
  운영한다.
- 기록 조회·수정·삭제·기본 공유와 AI 병원 전달본을 결제 없이 제공한다.
- 앱과 스토어 문구에서 상품, 가격, 구매, 복원, 남은 이용권과 결제 유도를 제거한다.
- 무료 빌드는 인앱결제 SDK를 초기화하거나 상품을 조회·동기화하지 않는다.
- 서버 공정사용 한도는 비용과 악용 방지에 필요한 범위로만 두고, 한도와 초기화
  시점을 명확히 안내한다. 결제나 참여코드로 우회하지 않는다.
- 현재 검증 대상은 전달본 생성·공유, 실제 병원 사용과 다음 방문의 기록 재사용이다.
- 병원 안내 저장은 방문 경계가 되며 이전 안내는 과거 기록에 보존한다. 다음 방문은
  사용자가 날짜·기간을 골라 재사용하고, 출처가 보이는 연결 UX 전에는 다른 방문의
  안내를 새 전달본에 자동 복사하지 않는다.
- 과거 결제 설계는 향후 별도 제품 결정이 있을 때만 다시 검토한다.
