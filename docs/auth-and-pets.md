# 계정과 반려동물

## 로그인

Google과 Apple 로그인을 기본 경로로 사용합니다. 기존 이메일 계정은 보조 로그인과
계정 복구를 위해 유지합니다. 활성화된 Provider만 화면에 표시하며 설정 조회가
실패하면 로그인 버튼을 숨깁니다.

- 웹 OAuth는 Supabase PKCE와 현재 허용된 웹 Origin만 사용합니다.
- 앱 OAuth는 `petflow://auth-callback`으로 돌아온 일회용 코드를 교환합니다.
- 로그인 중 받은 URL의 오류·코드·중복 콜백을 분리해 처리합니다.
- 로그인한 사용자가 직접 Google/Apple 계정을 연결할 수 있습니다.
- 이미 다른 계정이 소유한 identity는 자동 병합하지 않습니다.
- 모바일 세션은 OS 보안 저장소에 보관하며 일반 AsyncStorage에는 두지 않습니다.

운영 인증 정책은 다음과 같습니다.

- 익명 로그인은 허용하지 않습니다.
- 이메일 신규 가입은 받은 편지함의 확인을 마쳐야 사용할 수 있습니다.
- 이메일 비밀번호는 8자 이상이며 영문 대·소문자, 숫자, 기호를 모두 포함합니다.
- 로그인 화면에서 재설정 메일을 요청하고, 앱 또는 웹으로 돌아온 복구 세션에서
  같은 비밀번호 조건을 충족한 새 비밀번호를 저장할 수 있습니다.
- refresh token은 회전하며 짧은 재사용 구간만 허용합니다.
- CAPTCHA와 유출 비밀번호 조회는 외부 보호 키 또는 상위 요금제 적용 전까지
  미적용 상태로 운영 점검표에 남깁니다.

## 계정 정보

로그인 제공자의 계정 식별자와 이메일만으로 바로 시작합니다. 별도 닉네임,
전화번호, 주소나 법적 신원 입력을 가입 조건으로 요구하지 않습니다.

DB의 `tester_profiles`는 이전 앱 표시명 호환 때문에 유지합니다. 새 클라이언트는
이 테이블에 전화번호를 쓰지 않으며 기존 전화번호도 정리 마이그레이션에서 삭제합니다.

## 반려동물과 기록

- 사용자는 여러 반려동물을 등록·수정·삭제할 수 있습니다.
- `pets.user_id`와 RLS가 계정 소유권을 강제합니다.
- 기록은 서버가 인증 계정과 반려동물을 다시 확인한 뒤 저장합니다.
- 같은 반려동물의 기록은 서버가 시간 흐름(`episodes`)에 자동 연결합니다.
- 별도 경과 기록이나 흐름 마무리 절차를 요구하지 않습니다.
- 기록 수정·삭제와 사진·영상 연결도 서버가 소유권을 확인합니다.

## 탈퇴

로그인한 사용자가 앱 또는 웹에서 탈퇴를 확인하면 서버가 비공개 파일을 먼저
삭제하고 Supabase Auth 사용자를 삭제합니다. DB의 계정 소유 행은 외래 키
`ON DELETE CASCADE`로 함께 삭제됩니다. 파일 삭제가 실패하면 계정 삭제도 완료로
표시하지 않습니다.
