# PetFlow 기능 요구사항 점검표

이 문서는 `docs/product-direction.md`를 사용자 기능별 인수 조건으로 풀어 쓴다.
Android와 iOS 앱이 기준 제품이고, 웹은 같은 계정과 데이터를 다루는 보조 접근
경로다. 기능이 추가되거나 동작이 바뀌면 이 표와 관련 테스트를 함께 갱신한다.

## 판정 기준

- **자동 검증**: 정적 검사, 단위·API 테스트, 웹 빌드와 Expo 검사를 통과해야 한다.
- **DB 검증**: 마이그레이션과 pgTAP 계약을 실제 PostgreSQL에서 통과해야 한다.
- **운영 검증**: 외부 Provider, 메일, 스토어와 실제 기기가 필요한 출시 관문이다.
- 구현 코드만 존재하는 상태를 운영 성공으로 간주하지 않는다.

| 계정 복구 | 로그인 화면에서 재설정 메일을 요청하고 복구 세션에서 새 비밀번호를 저장한다. | 웹 `AccountView`, 모바일 `PasswordRecoveryModal` | 웹 빌드·앱 타입 검사 + 운영 메일·딥링크 검증 |
| 로그아웃 | 서버 세션과 기기 화면 상태를 정리하며 다른 사용자의 데이터가 남지 않는다. | 웹·앱 계정 처리 | 자동 검증 + 실기기 재로그인 검증 |
| 계정 탈퇴 | 비공개 파일을 지운 뒤 Auth 사용자를 삭제하고 과거 DB 결제 원장은 cascade로 함께 제거한다. 무료판 탈퇴는 RevenueCat 키나 외부 API 상태에 의존하지 않으며, PetFlow 저장소·Auth 삭제 실패를 완료로 표시하지 않는다. | `/api/account-deletion`, `deleteAccount` | API·DB 검증 + 운영 저장소 검증 |
| 최소 개인정보 | 로그인 ID와 이메일만으로 시작하고 전화번호·주소·위치·법적 신원을 요구하지 않는다. | 계정 UI, `202607280001_make_legacy_phone_optional.sql` | 자동 검증 + DB 검증 |

## 2. 함께하는 아이

| 요구사항 | 인수 조건 | 구현 위치 | 검증 |
| --- | --- | --- | --- |
| 여러 아이 관리 | 한 계정에서 여러 반려동물을 등록하고 선택·수정한다. 이름과 종류 외 항목은 선택이다. | 웹 `ProfileView`, 모바일 `PetManager` | 웹·앱 검증 + 실기기 입력 검증 |
| 프로필 사진 | 서버가 소유권을 확인해 업로드 경로를 발급하고 비공개 사진을 서명 URL로 표시한다. 사진 교체는 새 URL까지 확인한 뒤 이전 파일을 정리하며 URL 만료·직접 서명 실패 시 소유권 확인 API로 갱신한다. | `/api/pets/[petId]/photo-upload`, `/api/pets/[petId]/photo-url`, `pet-photos` 정책 | API·DB 검증 + JPEG·HEIC 실기기 재실행 검증 |
| 예방접종 | 강아지는 국내에서 쓰는 접종명 선택 목록과 기타 입력을 제공하되 권장 접종표로 표현하지 않는다. 병원·접종카드에서 확인한 주기를 한 번 선택하면 맞은 날 변경 시 다음 일정을 자동 계산하고, 저장 뒤에는 가장 가까운 일정만 보조 카드로 표시한다. 접종별 행을 분리해 다른 접종 기록을 덮어쓰지 않는다. | 모바일 `PetForm`, `vaccinations.ts`, `pet_vaccinations` | 앱 단위 테스트 + DB 검증 + iOS·Android 저장 완료 화면 검증 |
| 삭제 | 확인 후 해당 아이의 기록·미디어·흐름을 함께 삭제하고 다른 아이로 안전하게 이동한다. | `DELETE /api/pets/[petId]`, `deletePet` | API 테스트 + DB·저장소 검증 |

## 8. 출시 전 필수 운영 검증

아래 항목은 로컬 테스트 통과만으로 완료 처리하지 않는다.

1. 새 Google 계정, 기존 이메일 계정 연결, 중복 identity 거절을 Android와 iOS에서 확인한다.
2. Apple 일반 이메일과 비공개 릴레이 이메일 로그인을 각각 확인한다.
3. 이메일 확인과 비밀번호 재설정 링크가 웹·Android·iOS의 허용된 redirect로 돌아오는지 확인한다.
4. 두 계정과 두 반려동물로 RLS 교차 접근이 거절되는지 실제 DB에서 확인한다.
5. 사진·영상 업로드, 개별 삭제, 기록 삭제, 아이 삭제와 계정 탈퇴 후 Storage 잔존 파일을 확인한다.
6. Android와 iOS 설치본에서 결제 SDK 초기화·상품 조회·구매·복원·동기화가 실행되지 않고 AI 전달본을 결제 없이 만들 수 있는지 확인한다.
7. 현재 스토어 스크린샷과 심사 메모가 제출 빌드의 실제 무료 화면·기능·용어와 일치하는지 확인한다.
8. 새 계정으로 앱을 열어 병원 전달본 공유까지 3분 안에 끝나며 선택 입력이 진행을 막지 않는지 확인한다.

## 공통 검증 명령

```powershell
npm run db:start
npm run verify:all
```

`verify:all`은 Docker 기반 로컬 Supabase의 `supabase/tests/database.test.sql`까지
실행한다. Docker를 사용할 수 없는 환경에서는 `npm run verify:code` 결과와 DB 미검증
사유를 분리해 기록하고, CI나 Docker가 있는 환경에서 pgTAP을 완료한다. 원격 프로젝트는 배포 직전 `supabase migration list --linked`와
`supabase db lint --linked`로 로컬 마이그레이션과 일치하는지 확인한다.
